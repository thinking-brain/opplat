# Hicks Orchestration Log — 2026-03-21 13:19:52

## Scope
Inspect Keycloak/client-scope contract and bootstrap wiring

## Outcome
✅ Determined realm export was correct and compose/runtime scope needed pinning to `openid profile email offline_access`.

## Key Findings

1. **Keycloak Realm Status:** Verified that the imported realm (`docker/keycloak/opplat-realm.json`) was correctly configured with:
   - Default client scopes: `profile`, `email`, `roles`, `opplat-tenancy`, `opplat-api-audience`
   - Optional client scopes: `offline_access`
   - No misconfigurations in scope definitions

2. **Docker Compose Bootstrap Wiring:** Identified the root cause:
   - `docker-compose.yml` and `docker-compose.override.yml` do not set `VITE_AUTH_SCOPE` environment variable
   - Frontend services fall back to hardcoded scope defaults that included `roles`, causing login rejection

3. **Scope Contract Resolution:** Established that:
   - SPAs should request `openid profile email offline_access` 
   - `roles` must be a Keycloak default client scope, not an explicitly requested SPA scope
   - Docker Compose wiring must pin `VITE_AUTH_SCOPE` for both nginx and hot-reload paths
