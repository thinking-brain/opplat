**Timestamp:** 2026-03-23T11:25:28Z

**Role:** Reviewed proposal to flatten module Application projects into Opplat.Application module folders

## Assignment

Review the user's proposal to move MediatR handlers from `src/Modules/{Module}/Application/` into `src/Opplat.Application/{Module}/` while keeping module folders for discoverability.

## Outcome: REJECTED

**Verdict:** The proposal trades architectural integrity for marginal navigation convenience.

**Key Findings:**
- Breaks bounded context encapsulation — forces `Opplat.Application` to reference all module Domain + Infrastructure
- Bloats microservice deployables — each service would pull handlers for all modules, not just its own
- Contradicts prior approved decision (decisions.md @ line 2141) without new evidence
- Discoverable today via namespace convention and IDE solution folders

**Alternative:** Improve discovery via documentation, README pointers, and architecture diagram rather than restructuring.

## Contribution to Decision

This review provided the architectural assessment rejecting the flattening proposal on bounded-context and host-isolation grounds. The decision reflects the team's existing thin-host modular design and prevents accidental cross-module coupling.
