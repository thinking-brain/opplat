## Outcome Summary
Ripley identified critical architectural misalignments in OIDC scope configuration and role model constraints.

### Key Findings
1. **OIDC Scope Root Cause**: 
   - SPAs request only `openid` by default, missing `profile`, `email`, `roles`, `offline_access`
   - `docker-compose.yml` never sets `VITE_AUTH_SCOPE` environment
   - README claims `openid profile email offline_access` but code doesn't match
   - Backend validates `audience + roles`, not `scope`

2. **Role Model & Constraints**:
   - Roles are realm-level: `SuperAdmin`, `TenantAdmin`, `TenantUser`
   - Tenant scoping comes from user attributes/groups, not roles
   - Model is effectively single-tenant-per-user
   - TenantAdmin is not composite; gets both TenantAdmin + TenantUser roles

3. **Boundary Rules**:
   - Admin portal correctly bounded to `SuperAdmin` (UI + API)
   - Tenant operations require matching tenant identifier
   - Gap: client app root only requires auth, not tenant role enforcement

4. **Stale Guidance**:
   - README contains outdated local-JWT guidance

## Recommendations
- Frontends request `openid profile email`, add `offline_access` if refresh tokens needed
- Enforce tenant roles in client app root (prevent SuperAdmin access)
- Add scope-based API policies if authorization should be scope-driven
