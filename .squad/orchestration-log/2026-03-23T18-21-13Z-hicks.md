## Work Summary

Hicks fixed 2 of 3 code/configuration root causes preventing Aspire AppHost orchestration:

### 1. Path Resolution (FIXED)
- **Issue:** AppHost Program.cs used relative path strings (`../...`, `../../...`) that were resolved relative to the caller's working directory, not the repo root.
- **Example Error:** When running `dotnet run --project .\src\Opplat.AppHost\Opplat.AppHost.csproj` from `C:\projects\personal\opplat`, relative paths resolved to `C:\projects\personal\Opplat.MainApp\...` (wrong parent level)
- **Fix Approach:** Created `FindRepoRoot()` and `RepoPath()` helpers in Program.cs that compute absolute paths by:
  1. Starting from current assembly location
  2. Traversing parent directories until finding `opplat.slnx`
  3. Building absolute paths relative to repo root
- **Impact:** AppHost now works from any working directory (repo root, src/, AppHost dir, etc.)
- **Files:** `src/Opplat.AppHost/Program.cs`
- **Architecture Decision:** Keep path helpers in AppHost rather than pushing logic into service hosts. AppHost is the composition root and owns orchestration paths.

### 2. Endpoint Name Conflicts (FIXED)
- **Issue:** Aspire was loading HTTP endpoint definitions from two implicit sources:
  1. Individual project `launchSettings.json` files (all defaulting to name="http")
  2. Kestrel auto-detection via ASP.NET Core project defaults
  - Result: When `AddProject()` called `WithHttpEndpoint(...)`, Aspire found existing "http" endpoint and threw: `Aspire.Hosting.DistributedApplicationException: Endpoint with name 'http' already exists`
- **Fix Approach:** Created `ConfigureProjectDefaults()` helper that applies before any endpoint mapping:
  ```csharp
  static void ConfigureProjectDefaults(ProjectResourceOptions options)
  {
      options.ExcludeLaunchProfile = true;        // Skip launchSettings.json endpoints
      options.ExcludeKestrelEndpoints = true;     // Skip Kestrel auto-detection
  }
  ```
  - Applied to all 4 service projects in AddProject() calls
  - Then explicitly named each endpoint with unique, predictable names
- **Explicit Endpoint Naming:**
  - `mainapp-http` (8080)
  - `sales-api-http` (8083)
  - `inventory-api-http` (8082)
  - `admin-api-http` (8084)
  - `keycloak-http` (8180)
- **Architecture Decision:** Treat endpoint configuration as an AppHost-layer concern. Service hosts remain thin (no Aspire-specific dependencies). AppHost orchestrates both the host composition and the resource endpoint names.
- **Files:** `src/Opplat.AppHost/Program.cs`
- **Validation:** ✅ No duplicate endpoint name errors
