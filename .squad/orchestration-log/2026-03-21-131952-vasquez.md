# Vasquez Orchestration Log — 2026-03-21 13:19:52

## Scope
Inspect SPA runtime scope expansion and validate frontend scope defaults

## Outcome
✅ Found frontend scope expansion bug and aligned runtime/default/frontend wiring away from requesting `roles`.

## Key Findings

1. **SPA Scope Mismatch:** Both React SPAs were still requesting `openid profile email roles offline_access` at runtime despite local login requiring a narrower scope set:
   - `src/opplat-react/src/runtimeConfig.ts` defaulted to `openid`
   - `src/opplat-admin/src/runtimeConfig.ts` defaulted to `openid`
   - Both `auth/oidc.ts` files only force-appended `openid` as a required scope
   - README documented `openid` as the default

2. **Root Cause:** Fragmented configuration across multiple files caused scope drift:
   - Runtime-config fallbacks didn't align with Docker Compose VITE_AUTH_SCOPE
   - Frontend documentation wasn't aligned with Keycloak's actual scope contract
   - The `roles` scope cannot be requested from Keycloak (it's a mapper, not a consent scope)

3. **Alignment Path:** Established single default scope across all frontend layers:
   - Use `openid` as the shared baseline
   - Keep all defaults aligned in `runtimeConfig.ts`, `.env.example`, `Dockerfile`, and README
   - Allow environment overrides for provider-specific scope expansion
