## Architecture Overview
**Strategy:** Full database-per-tenant isolation with route-based + header-based resolution

**Key Components:**
1. **AppTenantInfo** — Tenant model implementing ITenantInfo
2. **Tenant Resolution** — Route pattern `/{__tenant__}/` + Header fallback `X-Tenant-Identifier`
3. **OpplatDbContext** — Updated to implement IMultiTenantDbContext
4. **JWT Enhancement** — Added tenant_id and tenant_identifier claims
5. **Tenant Provisioning Service** — Per-tenant seeding and migrations

## Design Decisions
| Component | Decision | Rationale |
|-----------|----------|-----------|
| **Package Version** | Finbuckle 7.0.1 | Latest stable for .NET 10 + EF Core 9.x |
| **Database Isolation** | Per-tenant databases | Maximum data security |
| **Tenant Store** | Configuration-based (in-memory) | Simple for initial 3 tenants; upgradeable to EF Core store |
| **JWT Signing** | Tenant-specific keys (optional) | Prevents cross-tenant token replay |
| **Backward Compatibility** | Kept legacy routes | Allows gradual client migration |

## Technical Specifications
- **Tenant Resolution Priority:** Route > Header (first match wins)
- **Fallback Connection String:** DefaultConnection used for non-tenant requests
- **Middleware Order:** `UseMultiTenant()` before `UseRouting()`
- **Identity Isolation:** Per-tenant admin users and roles
